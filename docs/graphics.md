# 그래픽 폴리시 (기획서 프롬프트 6)

기획서 3.3의 "인디 티 벗기는 핵심"을 구현한 부분. 전부 설정에서 개별로 끌 수 있다.

## 히트 필 3종

| 연출 | 파일 | 어떻게 |
|---|---|---|
| 흰 플래시 | `vfx/shaders/hit_flash.gdshader` + `vfx/hit_flash.gd` | 개별 스프라이트용. 적 무리는 `blob_multimesh` 가 `INSTANCE_CUSTOM` 으로 처리 |
| 히트스톱 | `core/combat/hit_stop.gd` | 크리티컬·보스 사망 시 `time_scale` 0.05 → 0.04초 후 복구 |
| 스쿼시&스트레치 | `vfx/shaders/squash_stretch.gdshader` | 정점 셰이더. 스케일 애니가 아니다 |

### 히트 플래시는 시간이 아니라 **프레임**으로 센다
히트스톱으로 `time_scale` 이 0.05가 된 상태에서 "0.03초 뒤 끄기"를 게임 시간으로 재면
실제로는 0.6초가 걸린다. 강타할 때마다 캐릭터가 하얗게 굳는다. 그래서 프레임 수로 센다.

### 히트스톱 복귀는 **실시간**으로 잰다
같은 이유가 반대로 적용된다. `_process` 의 delta 는 `time_scale` 이 곱해진 값이라,
0.04초를 그걸로 세면 0.8초가 된다. `Time.get_ticks_usec()` 을 쓴다.
크리티컬이 연달아 터져도 게임이 계속 느려지지 않게 최소 간격(0.22초)도 둔다.

## 데미지 넘버 — 개별 Label 금지

`vfx/damage_numbers.gd`. 기획서 6.2의 요구사항 그대로.

- 숫자 0~9 를 **SubViewport 로 한 번 구워서** 폰트 아틀라스를 만든다(흰 글자 + 어두운 외곽선)
- **글리프 하나가 MultiMesh 인스턴스 하나.** 120개 숫자 × 최대 6자리 = 인스턴스 720개, 드로우콜 1
- 동시 **120개 캡**. 넘치면 가장 오래된 것부터 밀어낸다
- 크리티컬은 **크기 1.5배 + 금색** (`#FFC94A` — 기획서 3.2의 플레이어 독점색)
- 설정에서 끄면 `EnemyManager` 가 시그널 자체를 쏘지 않는다(3,000마리면 초당 수천 번이다)

### 걸렸던 함정: QuadMesh 를 2D에서 쓰면 세로가 뒤집힌다
`QuadMesh` 는 3D 기준(+Y 위)으로 UV를 만드는데 2D는 +Y가 아래다. 그래서 텍스처의 V가 반대가 된다.
적/픽업을 그리는 `blob` 셰이더는 상하 대칭인 원이라 아무도 몰랐는데, 글자를 그리자마자
**"1"과 "4"가 거꾸로** 찍혔다("3"은 상하가 비슷해서 멀쩡해 보여서 더 헷갈렸다).
`vec2(UV.x, 1.0 - UV.y)` 로 뒤집어서 해결했다. MultiMesh 로 텍스처를 그릴 일이 또 생기면 같은 걸 조심할 것.

## 포스트프로세싱

- `data/gfx_environment.tres` — `WorldEnvironment` 글로우 0.6, 대비 +10%, 채도 +5%
- `vfx/shaders/vignette.gdshader` — 비네트. 기획서가 "강하면 촌스러움"이라 못 박아서 약하게 잡았다.
  실측으로 화면 코너가 중앙보다 **8% 어둡다** — 있는 줄도 모르게 있는 정도가 맞다.
- `vfx/shaders/chromatic.gdshader` — 색수차. 화면 가장자리에서만(가운데까지 번지면 눈이 아프다).

### 비네트는 화면 텍스처를 쓰지 않는다
원래 비네트와 색수차를 한 셰이더에 넣고 `hint_screen_texture` 로 화면을 다시 샘플했다.
그런데 **GL Compatibility 렌더러에서 카메라가 원점에서 멀어지면 백버퍼 복사가 빈 화면을 돌려준다.**
화면이 통째로 단색으로 덮인다. 저사양용 Compatibility 렌더러를 지원해야 하므로 그냥 못 쓴다.

비네트는 애초에 백버퍼가 필요 없다 — 어두운 테두리를 알파로 얹기만 하면 된다.
색수차는 화면 텍스처가 반드시 필요해서, `vfx/post_process.gd` 가 렌더러를 확인하고
Compatibility 면 그 노드를 꺼버린다. 대비/채도는 `WorldEnvironment` 가 맡는다.

## ★ 카메라 — 내장 position_smoothing 을 쓰지 않는다

Godot `Camera2D` 의 내장 위치 스무딩은 보간 가중치를 `speed * delta` 로 쓰는데
**이 값을 클램프하지 않는다.** 프레임이 한 번 크게 튀면(로딩 히치, 저사양 기기, 배속 테스트)
가중치가 1을 넘어 진동하다가 발산한다. 실측으로 카메라 변환이 `-10,000,000` 을 거쳐 **NaN** 이 됐고,
그 순간 **화면에서 월드가 통째로 사라졌다.** UI 는 별도 CanvasLayer 라 멀쩡히 남아 있어서
"렌더링이 깨졌다"가 아니라 "게임이 안 도는가?"로 한참 헤맸다.

`vfx/screen_shake.gd` 가 `1 - exp(-speed * delta)` 로 직접 따라간다.
delta 가 아무리 커도 가중치가 0~1 안에 있어서 최악의 경우 "즉시 따라붙기"가 될 뿐 발산하지 않는다.
`tests/run_tests.gd` 의 `test_camera_stability()` 가 0.9초짜리 프레임을 80번 먹여서 회귀를 막는다.

## 화면 흔들림 = 접근성 문제

`vfx/screen_shake.gd`. 랜덤 오프셋(화이트 노이즈)으로 흔들면 그냥 지직거린다.
`FastNoiseLite` 의 Perlin 을 시간축으로 훑어서 프레임 간 이동이 이어지게 한다.
흔들림 양은 trauma의 **제곱**에 비례한다 — 약한 타격은 거의 안 흔들리고 강타만 크게 흔든다.

`Settings.screen_shake = 0` 이면 완전히 멈춘다. 옵션 슬라이더로 조절한다(기획서 3.3).

## 바닥 (maps/ground_grid.gd)

M0 부터 **격자 선만** 그리고 있었다. 바닥색 자체는 `project.godot` 의 고정
`default_clear_color` 였고 `MapData.ground_color` 는 선 색으로만 쓰여서,
**맵을 바꿔도 바닥이 안 바뀌었다** — 혹한기와 연병장 바닥이 똑같은 국방색이었다.
화면 절반이 아무것도 없는 단색인 것도 여기서 왔다.

지금은 셋을 겹쳐 그린다.

1. **바닥색** — `MapData.ground_color` 로 칠한 사각형
2. **얼룩** — `vfx/shaders/ground_decal.gdshader`, MultiMesh 하나 (드로우콜 1개)
3. **격자** — 연병장 구획선. 얼룩이 생긴 뒤로 존재감을 낮췄다

### 얼룩

칸(128px)마다 정수 좌표 해시로 위치·크기·색을 뽑는다. **`randf()` 를 쓰면 안 된다** —
플레이어가 왔다 갔다 할 때마다 땅이 새로 생긴다. 색은 바닥색에서 밝기와 카키 쪽으로
아주 조금만 민다. 알파가 세면 땅이 아니라 구름·위장무늬로 보인다(실제로 그랬다).

그리는 범위는 카메라 줌에서 역산한다. 가로 1920 시절의 고정 12칸은 세로 화면에서
네 배를 헛그리는 것이었다.

`Settings.ground_decals` 로 끌 수 있고, 저사양 프리셋에서 자동으로 꺼진다.

### 바닥색은 어두워야 한다

기획서 3.2 의 "배경/지형 채도 40% 이하" 와 "플레이어는 항상 화면에서 가장 밝음"
둘 다 밝은 바닥과 양립하지 않는다. 게다가 `WorldEnvironment` 의 글로우 임계가
0.85 라 밝은 바닥은 화면을 하얗게 번지게 한다 — 혹한기 바닥을 휘도 0.6 으로 뒀더니
플레이어 주위가 통째로 흰 덩어리가 됐다. `tests/run_tests.gd` 가 맵마다 휘도 0.45
미만인지 검사한다.
